# Getting Help

Nanitics has three channels for different kinds of questions. Picking the right one
gets you a faster answer and keeps the right kinds of conversation in the right place.

## Discussions — open-ended questions, ideas, showcases

Use [GitHub Discussions](https://github.com/nanitics/nanitics/discussions) for:

- **Q&A** — "How do I…" questions that don't have a single right answer yet, questions
  about design trade-offs, usage patterns, best practices.
- **Ideas** — Half-formed proposals, "what if…" threads, features that aren't concrete
  enough to file as an issue.
- **Show and tell** — Share what you're building with Nanitics.

## Issues — reproducible defects and concrete feature requests

Use [GitHub Issues](https://github.com/nanitics/nanitics/issues) for:

- **Bugs** — Reproducible defects with repro steps, expected vs. actual behavior, and
  the version you saw it in.
- **Feature requests** — Concrete proposals with a problem statement and a proposed
  shape (API sketch or behavior description).
- **Documentation issues** — Typos, broken links, unclear guides, missing coverage.

Each has a template under [`.github/ISSUE_TEMPLATE/`](../.github/ISSUE_TEMPLATE/).

## SECURITY.md — vulnerabilities

**Do not file a public issue for vulnerabilities.** Use [GitHub Private Vulnerability
Reporting](https://github.com/nanitics/nanitics/security/advisories/new)
or email `security@nanitics.dev`. Full process and response SLAs in [SECURITY.md](../SECURITY.md).

## Not sure?

When in doubt, start in Discussions. If maintainers see a Discussion that belongs as
an issue, we'll ask you to file one and link it. The reverse is also fine — issues that
turn out to be questions get moved to Discussions with a link.
